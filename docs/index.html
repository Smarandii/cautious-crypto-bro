The model reads the post.
The code decides the trade.

Crypto Telegram channels are full of leverage claims, entry ladders and profit screenshots. This project reads them — text, images, albums — and turns them into orders, but only through a fixed pipeline where a language model is allowed to interpret and is never allowed to decide money.

One dividing line

A language model is good at reading a messy human post and bad at arithmetic under a clock. So the split is deliberate and narrow:

The model may

  • Read text, images and albums
  • Name a symbol and a direction
  • Recognise entry, reduce, close and cancel intent
  • Copy the trader's stated leverage
  • Say “this is ambiguous” and stop

The model may not

  • Choose a position size
  • Pick a stop, target or ladder level
  • Set or move leverage
  • Submit, amend or cancel an order
  • Approve its own extraction

Every level a trader sees is arithmetic over a frozen capital base and a price-risk budget — a 1% default, with a deterministic 2% fallback stop when the post omits one. Because no wall clock, randomness or network call sits inside planning, a plan can be replayed offline and compared against what actually happened.

The pipeline

Untrusted input enters on the left. By the time anything reaches the exchange, it has passed through four gates that each get to say no.

Failure is the interesting part

Any system that places orders has to decide what to do when reality is ambiguous. Here, ambiguity is a state, not an error to be retried.

Uncertain stays uncertain

When a cancellation or lifecycle action cannot be resolved from current evidence, the strategy is parked as UNCERTAIN and the exchange is left alone. A restart never retries it automatically, and recovery is a deliberate human decision.

Accepted-but-unknown is quarantined

If a submission may have reached the exchange, it is quarantined rather than resent. A pre-submit failure is different: it closes the empty strategy outright. Retrying either case blindly is how one bad signal becomes two positions.

One owner per position

Both manual and automatic routing refuse symbols already controlled by an active strategy or by live exposure and orders. Independent ladders cannot share a net position.

Missed posts still arrive

Each channel is reconciled against history on a fixed interval. Only a history scan advances the recovery cursor, so a newer live message cannot hide an older missed post. Album downloads survive batch boundaries and retries.

Rigor over features

The pull request gate is the same locally and in CI: format, lint, type check, build, and the full test suite. Application code is held to a cyclomatic complexity ceiling of 10; operator scripts and tests are exempt because they are linear procedures.

  • ruff format and ruff check — formatting and lint
  • pyright — static types over src/
  • pytest — 358 tests, offline boundaries, real temporary SQLite
  • uv build and uv lock --check — reproducible packaging
  • dockerfile-roast — Dockerfile linting at warning severity
  • docker compose config and a real image build
  • CodeQL — security-extended analysis of Python
  • dependency-review — advisory gate on every pull request

Live Bybit Demo testing is deliberately opt-in and bounded: small notional, a frozen risk cap, one symbol at a time, and evidence written out with hashes and cleanup receipts. If cleanup fails, the app stays paused.

What this is not

Demo only. No performance claims.

This repository targets Bybit Demo trading. It is not configured for mainnet, and no part of it should be pointed at real funds.

There are no published return, drawdown or win-rate figures here. The comparison of the final implementation against forensic replay — drawdown, full-stop losses, profit give-back, realized R after costs and fill quality — is listed as open work and has not been completed. A passing test suite is not a track record.
